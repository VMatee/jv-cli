# JV CLI 0.5.1

- Compatible clients can display validated public JV support codes, such as `JV-SVC-103`, `JV-SVC-002` and `JV-TIMEOUT-001`, when remote work needs attention or fails.
- Administrator authentication attention keeps the turn active. After the administrator restores service authentication, JV CLI continues polling the same job without submitting it again.
- Unknown or malformed support fields are omitted. Only reviewed public explanations are forwarded; private provider diagnostics remain hidden.
- Remote support details clear before the next turn, so a local failure cannot inherit an earlier provider code.

Integration clients continue using bridge protocol 1. Terminal `turn.failed`
events can include optional remote support fields, and nonterminal `turn.status`
events can report `waiting_for_auth` and recovery to `running`. Legacy protocol-1
clients retain their existing generic failure behavior. See the bridge contract
for the optional fields and validated public-message vocabulary.

Existing Linux permissions and Windows trusted-host execution are unchanged.
Windows workers explicitly select `--execution-mode trusted-host`, granting tools
the normal account's filesystem and network access without approval prompts.
Use an ordinary dedicated account and keep Windows Firewall enabled. Windows
requests requiring network isolation remain unsupported and fail closed.

Codex remains pinned to 0.149.1; no server contract change is required. Stop is
local cancellation and remote job state may remain unknown. Windows installers
remain unsigned; verify download bytes with the release's `SHA256SUMS`.
