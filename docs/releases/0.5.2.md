# JV CLI 0.5.2

- Compatible clients can display validated public support codes, including `JV-SVC-103`, `JV-SVC-002` and `JV-TIMEOUT-001`, when remote work needs attention or fails.
- Administrator authentication attention keeps the turn active. Once authentication recovers, polling continues for the same job without a duplicate submission.
- Only reviewed public explanations are forwarded. Malformed or untrusted support fields are omitted, and private provider diagnostics remain hidden.
- Remote support details clear before the next turn, preventing stale codes on local failures.

Bridge protocol 1 is unchanged. Its optional remote failure fields and nonterminal
`turn.status` events support `waiting_for_auth` and recovery to `running`.
Legacy clients retain generic failure behavior.

The 0.5.1 tag did not publish release assets. This version retains its accepted
runtime functionality and corrects the release workflow permissions needed by
the existing verification gate. See the [release history note](../RELEASING.md#unpublished-051-tag).

Linux permissions and explicit Windows trusted-host execution are unchanged.
Windows trusted-host grants tools the normal dedicated account's filesystem and
network access without approval prompts. Keep Windows Firewall enabled;
requests requiring Windows network isolation remain unsupported and fail closed.

Codex remains pinned to 0.149.1. Stop remains local cancellation, with remote job
state potentially unknown. Windows installers remain unsigned; verify download
bytes using the release's `SHA256SUMS`.
